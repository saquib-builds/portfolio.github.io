AI RESEARCH AGENT

A research-focused AI system built from first principles — evolving from rule-based logic into a modular Planner → Researcher architecture with live web research, structured outputs, evidence guardrails, logging, and automated testing.

01

THE PROBLEM

A chatbot answers. A research agent investigates.

I wanted to understand what changes when an LLM stops being the whole application and becomes one component inside a larger system.

Research requires current information, planning, tool use, evidence handling, source judgment, and a way to continue after external tools return results.

CORE QUESTION

How do you move from “ask the model” to a system that can plan, research, validate, and synthesize?

02

THE SOLUTION

Separate thinking about what to research from actually researching it.

PLANNER

Creates a structured research objective and ordered steps.

Pydantic gives the planner output a reliable schema instead of leaving downstream code to interpret free-form text.

RESEARCHER

Executes the plan using current external information.

The researcher uses web search, prioritizes stronger sources, and synthesizes evidence into the final answer.

03

EVOLUTION

I didn’t start with the final architecture. I earned it version by version.

V1

Rule-based research

Simple Python conditions taught me deterministic routing and basic control flow.

V2

LLM integration

Decisions moved from fixed rules into model-generated reasoning.

V3–V4

Tools & function calling

I learned that a model can request a tool, but application code still has to execute it.

V5–V7

Agent loop + web research

Tool results were returned to the model and the loop continued until a final answer emerged.

V8

Planning

The research problem was separated into planning first, execution second.

V9

Production-style engineering

Modular architecture, structured outputs, logging, error handling, tests, and evidence guardrails.

05

ENGINEERING QUALITY

It should fail clearly, not mysteriously.

The final version includes safeguards around inputs, model output, API errors, research behavior, and automated verification.

STRUCTURED OUTPUTPydantic

Planner output is validated before the researcher consumes it.

OBSERVABILITYLogging

Important workflow stages and expected failures are visible in the CLI.

ERROR HANDLINGTargeted exceptions

Authentication, rate limits, timeouts, connectivity, and bad requests are handled separately.

RESEARCH QUALITYEvidence guardrails

Primary and authoritative sources are preferred over weaker secondary sources.

TESTINGMocked dependencies

Core components are tested without spending API credits on live calls.

ARCHITECTURESeparation of concerns

Planner, researcher, prompts, models, config, and orchestration remain independent.

06

LESSONS

The useful lessons were mostly between the features.

01

Tool calling is only a request.

The application still has to execute the tool, return the result, and let the model continue.

02

State matters in an agent loop.

Losing context can make an agent repeat the same action even when the tool already succeeded.

03

LLM output becomes safer when software can validate it.

Structured schemas reduce ambiguity between AI components.

04

More research is not automatically better research.

Source quality, stopping criteria, and response depth matter just as much as search volume.
